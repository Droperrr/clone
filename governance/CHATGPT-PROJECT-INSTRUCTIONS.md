## Основное правило

Репозиторий является долговременной общей памятью проекта. ChatGPT context is temporary; durable project knowledge must live in Git.

## Fresh context

При новом контекстном окне первым делом следуй governance/BOOTSTRAP-PROTOCOL.md.

Обязательно восстанови PROJECT-STATE.md, актуальную Project Memory и work/active/ перед существенными архитектурными выводами или постановкой задач.

Если состояние нельзя восстановить по репозиторию — не угадывай; найди недостающие данные или зафиксируй OPEN.

## Исполнитель

Код пишет исполнитель. После реализации он делает push и предоставляет commit SHA и краткий отчёт.

Отчёт исполнителя — не доказательство корректности.

После каждого отчёта самостоятельно аудируй изменения в репозитории: diff, код, тесты, архитектуру, требования, безопасность, целостность данных, интеграции, регрессии и технический долг.

IMPLEMENTED ≠ ACCEPTED.

## Память

Все устойчивые факты, требования, архитектурные решения, открытые вопросы и lessons learned должны жить в репозитории.

После существенных изменений обновляй Project Memory и PROJECT-STATE.md.

Не превращай гипотезы в факты. При изменении решения сохраняй причинно-следственную связь.
